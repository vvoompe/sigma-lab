# Незалежна перевірка серверної інструкції Z4 — 19.10.2026

Контекст: #13, #9, PR #31. Перевірку виконав агент від імені Юри (@otmepush),
окремо від прогону агента Артема. Це не ручний прогін людини й не нова віртуальна машина.

## Що саме перевірено

Створено новий клон `fix/30-checkpoint-ci`, коміт
`5fbf7e40b86af933990bc85f96746ce3b59b5bce`. На початку не було bin/obj/TestResults.
SDK, Docker, JDK/Android SDK і спільний кеш NuGet уже були на машині. Серверна перевірка
не використовувала MAUI workloads. ОС sandbox за Environment.OSVersion — Windows NT
10.0.19045.0; PowerShell 7.6.5, Python 3.12.14, .NET SDK 10.0.401,
dotnet-ef 10.0.12, PostgreSQL 15. PostgreSQL була окремою тестовою базою з унікальним
іменем; для запуску API створено ще одну окрему базу. SQLite-файли також нові.

Перевірявся README запропонованого PR #31, а не непідтверджена наявність його змін у main.
Результати цього коміту не можна називати результатами поточного HEAD будь-якої іншої гілки.

## Середовище та необхідні відхилення

- Перший `dotnet tool restore` не зміг прочитати HTTPS-індекс NuGet у Windows sandbox.
  Повтор із зовнішнім локальним NuGet config через relay на loopback успішний.
  Relay звертається до api.nuget.org через HTTPS із перевіркою сертифікатів.
  Зміни конфігурації репозиторію для цього не робились.
- `DOTNET_CLI_HOME` був окремим каталогом перевірки; використовувався наявний кеш пакетів.
- Docker API недоступний sandbox через named pipe. Користувач запустив окремий
  тестовий контейнер, після чого агент підключився до PostgreSQL на localhost:55434.
- Перший запуск API впав через заборону запису в Windows Event Log для sandbox-акаунта.
  Повтор із `Logging__EventLog__LogLevel__Default=None` успішний; console logging
  залишався увімкненим. Код API та міграцій не змінювався.

Отже, це незалежна перевірка нового клону з описаними адаптаціями середовища,
а не твердження, що на будь-якій чистій Windows дослівні команди пройдуть без підготовки.

### Міграції та API

Виконано `dotnet ef database update` для обох проєктів міграцій з конфігурацією Release
та окремими підключеннями. У кожній БД застосовані InitialCreate, DomainModel, SiteOwnership.
`dotnet ef migrations list` для SQLite показав усі три застосовані міграції.

SQLite друкує runtime warning про нетранзакційний PRAGMA під час rebuild.
Перша спроба підключення до ще не створеної PostgreSQL також логується перед створенням
бази. Обидва CLI-прогони завершилися `Done`, exit 0; це не попередження компілятора.

API запущено з Release DLL із робочим каталогом `src/Lab.Api`, увімкненими startup-міграціями,
власними новими базами та описаним вище вимкненням Event Log. Це еквівалент перевірки
зібраного API, а не дослівний запуск README через `dotnet run`.

| Провайдер | Перевірка | Результат |
|---|---|---|
| SQLite | GET /api/sites?page=1&pageSize=2 | 200; порожня сторінка, page=1, pageSize=2 |
| SQLite | GET /openapi/v1.json | 200; схема містить /api/sites |
| PostgreSQL | GET /api/sites?page=1&pageSize=2 | 200; порожня сторінка, page=1, pageSize=2 |
| PostgreSQL | GET /openapi/v1.json | 200; схема містить /api/sites |

Після перевірки обидва запущені API-процеси зупинені.
