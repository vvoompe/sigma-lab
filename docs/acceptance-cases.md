# Приймальні кейси

Фіксований список кейсів, за яким оцінюється функціональна коректність продукту. Список
**затверджується на ЧП1** і далі не змінюється без домовленості з викладачем.

Правила:
- кожен кейс має бути **автоматизованим** тестом (бажано) або відтворюваним скриптом;
- у колонці «Стан» ставиться `✅` лише тоді, коли кейс проходить у CI;
- зміна очікуваної поведінки - це зміна контракту: issue + PR + позначка в описі PR для всієї команди.

## Коди відповідей на доступ до чужих ресурсів (зафіксовано)

Єдине рішення для всієї системи, щоб клієнт поводився передбачувано:

- **404** - читання ресурсу, якого немає **або** який належить іншому користувачу: існування
  чужого ресурсу не розкриваємо;
- **403** - спроба **зміни** ресурсу, який існує, але прав на дію немає;
- **409** - ресурс доступний, але дія конфліктує з його станом (підписана серія, дубль).

Це рішення продубльовано в `docs/ARCHITECTURE.md`, розділ 7.

## Мінімум для ЧП1

**Кейси 8 і 9** перевіряються тестами `SiteServiceTests`; `SitesApiTests` додатково
перевіряє HTTP-створення 201 з Location та читання створеного майданчика.

Кейси **21 і 22** реалізовано для наявного ресурсу Site у першій частині #6.
`pageSize` понад 100 обмежується без помилки, далека сторінка повертає 200 і порожній
`items`. Друга частина #6 додає таку саму поведінку для приладів, серій і вимірів.
Очікування кейсів не змінювалися.

### Автоматизація другої частини #6

`ResourceApiTests` перевіряє HTTP-кейси 7, 10–13, 16–18, 21–23, а також CRUD
приладів/серій і декларації OpenAPI. `ResourceRaceApiTests` додає конкурентні
UUID/SerialNumber/FK-сценарії разом із `ResourcePostgresApiTests`; останній
перевіряє статистику та відкат видалення/аудиту після конкурентного підпису на
живій PostgreSQL. Це доповнює доменні тести, а не замінює їх.
Статуси цих кейсів залишено без нових позначок до проходження CI цього PR.
Кейс 14 стосується окремого sync endpoint: звичайний POST виміру на дубль дає 409.
Підпис через HTTP (19), зміна окремого виміру (20), sync і експорт цим PR не заявлені.

[CI PR #25](https://github.com/vvoompe/sigma-lab/actions/runs/38275301547) успішний:
25 тестів домену + 58 тестів застосунку + 20 тестів PostgreSQL, 0 падінь/пропусків;
8 Python-перевірок CLI порога покриття.

Решта кейсів закривається зонами Z1, Z3 і Z4 за планом чекпоінтів.

### Перевірка Z3, issue #8

Кейси 5 і 6 пройшли CI у [PR #27](https://github.com/vvoompe/sigma-lab/pull/27):
усі п'ять перевірок успішні. Локальні `AuthApiTests` перевіряють реєстрацію,
дубль email, однакове тіло 401 для хибного пароля й невідомого email, lockout
після п'яти спроб, заборону самозміни ролі та аудит адміністративної зміни.
Кейси 1–4 залишаються без `✅`, доки їх не підтвердить CI credentials PR.
Для Site додано локальні HTTP-тести власності: чужий майданчик не повертається у списку
й дає 404 на читанні та 403 на зміні. Це не закриває кейс 7 (читання чужої серії),
який залишається очікувати сервісного/API контракту серій та CI.
