# Еталонні серії для перевірки розрахунків

Навіщо цей файл: кейси 16-18 приймальних вимог перевіряють **числа**, а не факт відповіді.
Тут зафіксовані вхідні дані й очікувані результати, щоб HTTP-тести, ручна перевірка через API
і юніт-тести ядра спиралися на одні й ті самі значення.

Числа обчислені незалежною реалізацією (Python: `statistics.stdev` і МНК вручну), а потім
звірені з ядром `src/Lab.Application/Statistics` тестом `ReferenceSeriesTests`. Допуск звірки -
`1e-9`. Якщо ядро колись розійдеться з цим файлом, тест упаде - саме цього ми й хочемо.

## A. Однорідна серія: середнє, СКО, похибка, інтервал

Вхід - 11 вимірів в одній одиниці (°C), у цьому порядку:

```
12.1  12.4  11.9  12.0  12.6  12.2  11.8  12.3  12.5  12.15  12.35
```

| Показник | Очікуване значення |
|---|---|
| Кількість вимірів | 11 |
| Середнє | 12.209090909090909 |
| Вибіркове СКО (n−1) | 0.249818115654351 |
| Стандартна похибка (СКО/√n) | 0.075322995950827 |
| Критичне t (95 %, df = 10) | 2.228138851986274 |
| Довірчий інтервал 95 % | 12.041260815364867 … 12.376921002816951 |

Ці числа закривають кейс 16 («числа збігаються з еталоном у межах похибки»): порівнюються
середнє, СКО, похибка та межі інтервалу.

## B. Серія з промахом: правило 3σ

Вхід - та сама серія A плюс значення **15.0** у кінці (індекс 11, нумерація з нуля):

| Показник | Значення |
|---|---|
| Кількість вимірів | 12 |
| Середнє | 12.441666666666666 |
| Вибіркове СКО | 0.840138877408571 |
| Поріг 3σ | 2.520416632225712 |
| Відхилення 15.0 від середнього | 2.558333333333334 |
| Результат | значення з індексом 11 позначається як викид, дані **не видаляються** |

**Межа правила, яку треба знати й казати на захисті.** Якщо замість 15.0 узяти 14.5, то поріг
3σ стає 2.108748, а відхилення - 2.100000, і правило промах **не** позначить. Це не дефект
реалізації: на короткій серії сам промах роздує СКО, через що поріг росте разом із ним. Тому
`MeasurementAnalysis.FindOutliers` описаний як евристика, а не як доказ помилки виміру. Для
коротких серій надійніше порівнювати з діапазоном приладу (`Instrument.ValidateMeasurement`)
або з еталоном у межах допуску.

## C. Серія з трендом: лінійна регресія

Вхід - 8 пар (час у хвилинах, температура в °C):

```
x = 0  1  2  3  4  5  6  7
y = 20.0  20.6  21.1  21.9  22.4  23.0  23.7  24.3
```

| Показник | Очікуване значення |
|---|---|
| Нахил (slope) | 0.616666666666667 |
| Вільний член (intercept) | 19.966666666666669 |
| R² | 0.998541210795040 |
| RMS залишків = √(SSE/n) | 0.054006172486731 |
| Прогноз у точці x = 10 | 26.133333333333333 |

RMS тут - не оцінка залишкового СКО `√(SSE/(n−2))`, а `√(SSE/n)`. Прогноз поза діапазоном
вимірювань є екстраполяцією і фізичної достовірності не гарантує.

## D. Порівняння з еталоном

| Вхід | Очікування |
|---|---|
| середнє серії A = 12.2090909…, еталон 12.2, допуск 0.5 °C | відхилення 0.009090909090909, `withinTolerance = true` |
| те саме, допуск 0.005 °C | `withinTolerance = false` |

Допуск включний: рівність `|value − reference| == tolerance` вважається входженням у межі.
Одиниці не конвертуються автоматично - вони мусять збігатися.

вимірювання, а не лише «щось порахувалось».
