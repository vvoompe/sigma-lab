# Фоновий обробник — Z4, #15

`SyncWorker` перевіряє БД, обходить серії сторінками по 100 ключів і викликає
`SeriesProcessor`. Для незміненої версії з опублікованим маніфестом перерахунок
пропускається. Зміна вимірів/серії підвищує доменну Version і створює новий кеш.

## Перерахунок і файли

В узгодженій Serializable-транзакції читаються серія, її прилад і виміри.
Статистика викликає спільний `SeriesStatistics` із Z1. Для 0 вимірів середнє
відсутнє; для одного є середнє, але немає вибіркового СКО та стандартної похибки.
Сам перерахунок використовує масив значень для незміненого математичного ядра.

Експорт відокремлений від перерахунку: CSV і JSON читають виміри через
`AsAsyncEnumerable`, без `ToList`/`ToArray` та без tracking усієї колекції.
CSV — UTF-8 з BOM, інваріантний формат чисел, UTC ISO 8601, екранування лапок
і захист текстової колонки одиниці від формул електронних таблиць.

На виході: `series-{Id}-v{Version}.csv`, `.json`, `.manifest.json`.
Маніфест містить статистику й версію та публікується останнім, після обох файлів.
Споживач обирає тільки набори з маніфестом. Це відновлюваний файловий кеш,
а не нова доменна сутність чи міграція. OutputDirectory має бути окремим для кожної БД.
Старі завершені версії зберігаються; автоматична чистка видаляє лише тимчасові
`series-*.tmp`, старші за добу. Каталог не слід спільно використовувати різними Worker.

При помилці однієї серії решта обробляється далі, невдала повторюється наступного
циклу. При штатній зупинці CancellationToken передається до EF, файлів і затримок;
тимчасові файли прибираються у finally, завершення не пишеться як помилка.

## Налаштування

- `Worker:IntervalSeconds`: 300 за замовчуванням, мінімум 5.
- `Worker:OutputDirectory`: `exports` біля застосунку за замовчуванням.
- `Database:MigrateOnStartup`: true, можна вимкнути після застосування міграцій.
- `LAB_DB_PROVIDER`, `ConnectionStrings__Postgres` / `ConnectionStrings__Sqlite`:
  спільний механізм інфраструктури. Секрети задаються тільки через середовище.

```powershell
dotnet run --project src/Lab.Worker/Lab.Worker.csproj -c Release
```

## Окремий Docker-стек для перевірки

Compose належить демонстрації #15; загальна доставка стека — #10 / Z2.
Потрібен Docker Desktop. Задайте в середовищі або зовнішньому env-файлі:
`LAB_PG_PASSWORD` і випадковий `LAB_JWT_KEY` (не менше 32 байтів).
Не додавайте файл із секретами в Git.

```powershell
docker compose --env-file <зовнішній-env-файл> -p sigma-z4 -f src/Lab.Worker/compose.yml up --build -d
docker compose --env-file <зовнішній-env-файл> -p sigma-z4 -f src/Lab.Worker/compose.yml logs -f worker
```

API: `http://localhost:5085` тільки на loopback; PostgreSQL: localhost:55435.
Порти можна змінити через `LAB_API_PORT` / `LAB_PG_PORT`. HTTP тут призначений
для локальної інтеграційної перевірки; MAUI потребує HTTPS із довіреним сертифікатом.
Для роботи клієнта підключіть HTTPS termination або власний HTTPS-хост API.
Не відкривайте демонстраційний HTTP-порт у зовнішню мережу.

PostgreSQL має healthcheck; API та Worker використовують одну БД, обидва мають
спільні міграції. Worker працює як непривілейований користувач; `/exports`
зберігається в окремому volume. Dockerfile включає runtime-бібліотеку Kerberos,
яку завантажує Npgsql на Linux. Dockerfile.dockerignore передає тільки вихідні
файли src і конфігурацію збірки, без work, секретів, bin/obj та старих звітів.

У журнал потрапляють події 3000 (старт), 3001 (доступність БД), 3002 (серія
оброблена), 3003 (збій циклу), 3004 (збій окремої серії). Повтор незміненої
серії не створює нову подію 3002 та не перезаписує завершені файли.

Експорт у файли не реалізує HTTP CSV endpoint кейсу 24 — це контракт API / Z2.
