# Декларування використання ШІ (META-USAGE)

**Проєкт:** STEM-проєкт «Польова лабораторія», дисципліна «Мультиплатформне програмування».
**Команда «Сігма»:** Саша - Z1 (дані, схема, розрахункове ядро), Артем - Z2 (контракти, API, CI,
Docker), Ваня - Z3 (безпека й доступ), Юра - Z4 (клієнт MAUI, синхронізація).

---

## 1. Як ми працюємо з ШІ (спільне)

Ми використовуємо агентні асистенти з доступом до файлів і терміналу. Домовленість у команді:

- ШІ пише код і тексти; рішення ухвалює людина і відповідає за результат.
- Після кожної зміни - `dotnet build -c Release` (нуль попереджень) і `dotnet test`; вивід
  додається в опис PR.
- Фрагмент, який автор не може пояснити, у `main` не потрапляє. Заглушки, `TODO` і тести,
  підправлені під зелений CI, заборонені.

Кафедра вимагає декларувати використання ШІ - тут ми це й робимо: по кожній зоні видно, які
інструменти застосовувалися, для чого саме і як результат перевірено. Розписувати кожну дрібну
правку не потрібно, тому нижче - те, що визначало роботу над проєктом.

## 2. Саша - зона Z1 (дані, схема, розрахункове ядро)

**Інструмент.** Агентний асистент із доступом до файлів, терміналу й читання GitHub, модель
через API. Додатково бібліотека MathNet.Numerics 5.0.0 (MIT) - квантиль Student t.

**Що згенеровано.** Домен `src/Lab.Domain/**` (User, Instrument, ReferenceValue, Experiment,
Measurement), Fluent-конфігурації, по дві міграції на кожну СУБД, розрахункове ядро
`src/Lab.Application/Statistics/**`, тести, `docs/data-model.md` і `docs/statistics-core.md`.

**Ключові рішення, які я ухвалював.** Мінімальний профіль User без автентифікації - її робить Z3;
одна серія - один прилад і одна одиниця; `Site.OwnerId` став nullable FK, а старі значення
збережено в `LegacyOwnerId`, щоб не створювати фіктивних користувачів; викиди за правилом 3σ
лише позначаються, а не видаляються.

**Як перевірено.** `dotnet build -c Release` - нуль попереджень. `dotnet test` на SQLite і на
окремій PostgreSQL 15: 185 тестів, 0 падінь (це число на момент злиття PR #26; у поточному
`main` - 226: 63 домен + 135 застосунок + 28 PostgreSQL). Міграції перевірено в обидва боки,
зокрема збереження вже наявних даних. Тести відтворили дефекти до виправлення - втрату дисперсії
через underflow і хибний прогноз із непредставним середнім.

**Мікрозміни до захисту.**
1. Змінити рівень довіри й показати, як від цього змінюється ширина інтервалу.
2. Змінити поріг викидів або допуск і додати граничний тест.

## 4. Ваня - зона Z3 (автентифікація, ролі, володіння ресурсами, аудит)

**Інструмент.** Copilot SDK у VS Code; локальні файли, .NET SDK 10.0.100 і xUnit.

**Ключовий запит.** Підготувати перший PR для issue #8 після злиття Z1, почавши з bearer
автентифікації, трьох ролей, `ICurrentUser` і негативних HTTP-тестів, не реалізуючи решту
milestone автентифікації.

**Що згенеровано.** `ICurrentUser` читає числовий `sub` і роль із перевірених claims.
API приймає лише підписані HS256 JWT із терміном дії, визначеними issuer/audience та
`ClockSkew = 0`; ключ береться тільки зі змінної середовища `Jwt__Key` і має не менше
32 байтів UTF-8. Issuer — `sigma-lab`, audience — `sigma-lab-api`. Fallback-політика
захищає endpoint-и підтримуваними ролями, не змінюючи контролери Z2. Зареєстровані
окремі політики Researcher, LabManager і Administrator.
Bearer-схему додано до OpenAPI; README пояснює локальне безпечне створення ключа.

**Як перевірено.** `dotnet build LabStem.Server.slnf -c Release --nologo` — 0 попереджень,
0 помилок. `dotnet test LabStem.Server.slnf --nologo` — 225 пройдено, 0 помилок,
10 штатних пропусків PostgreSQL-тестів без `LAB_TEST_POSTGRES`. HTTP-тести перевіряють
401 без токена й із хибним підписом, 403 із невідомою роллю, а також успішні запити
з дійсним тестовим токеном. Загальні команди `dotnet build -c Release` і `dotnet test`
з кореня також запущено, але вони зупинилися на відсутній MAUI workload `maui-android`
(NETSDK1147); MAUI-клієнт не входить до цієї серверної перевірки.

У наступному етапі #8 реалізуються credentials, реєстрація/вхід, адміністративна
зміна ролі з аудитом і перевірка власності Site; аудит підпису серії ще залишається.
Для зміни схеми потрібне рев'ю Z1, для DTO й endpoint-ів - рев'ю Z2.

**Другий етап Z3.** Додано `UserCredential` зі спільним PK/FK до профілю `User`,
`AuditEntry`, `PasswordHasher<UserCredential>`, реєстрацію/вхід із HS256 access token,
lockout після 5 помилок на 15 хвилин і `PATCH /api/admin/users/{id}/role`.
Парольна політика, погоджена з автором: 12–128 символів без вимог до складу;
токен чинний 30 хвилин. Роль реєстрації завжди `Researcher`; хеш не повертається.
Для обох СУБД створені окремі міграції. `AuthApiTests` перевіряють HTTP-поведінку,
а SQLite migration test - зв'язок і UTC. Acceptance кейси 1–4 до CI credentials-гілки
не позначаються виконаними; її CI/PR ще не створено.

**Локальна перевірка другого етапу.** `dotnet build LabStem.Server.slnf -c Release` —
0 попереджень і 0 помилок; `dotnet test LabStem.Server.slnf -c Release` — 242 пройшло,
0 падінь, 10 штатних пропусків PostgreSQL. SQLite міграції застосовані в інтеграційному
тесті; EF перевірив обидва snapshots. Живої PostgreSQL на localhost:55432 не було,
тому міграцію Postgres і повний тестовий цикл на ній потрібно виконати в CI або з
доступною тестовою БД. Обов'язкові кореневі `dotnet build -c Release` і `dotnet test`
зупинилися на NETSDK1147 через відсутній `maui-android`; серверний solution filter
пройшов. Credentials PR/CI ще не створені.

**Третій етап Z3 — власність Site.** Створення, список, читання й оновлення майданчиків
обмежено перевіреним `ICurrentUser.Id`; чужий Site повертає 404 на читанні та 403 на
зміні. Додано `PUT /api/sites/{id}`, DTO запиту, OpenAPI й тести сервісу та HTTP.
`dotnet build LabStem.Server.slnf -c Release` — 0 попереджень і помилок;
`dotnet test LabStem.Server.slnf -c Release` — 245 пройшло, 0 падінь, 10 штатних
пропусків PostgreSQL. Це локальні результати, не CI; PostgreSQL на localhost:55432
недоступна. Кореневі `dotnet build -c Release` і `dotnet test` повторно завершилися
NETSDK1147 через відсутню workload `maui-android`. Перевірку невірної залежності
`ICurrentUser` у тестовому DI та очікувань типу винятку виправлено, поведінку продукту
не послаблювали. Контракт PUT потребує рев'ю Z2 перед PR merge; схема credentials —

## 6. Порівняння підходів (питання на захисті)

| Підхід | Переваги | Обмеження в нашому проєкті |
|---|---|---|
| Генерація агентом із доступом до терміналу | швидкий цикл «зміна → збірка → тести», видно реальний вивід | агент схильний пропонувати звичні шаблони (наприклад, один набір міграцій на дві СУБД) |
| Чат-асистент без доступу до файлів | швидкі відповіді на теоретичні питання | не перевіряє, що код справді збирається; результат треба переносити руками |
| Написати самому з документацією | глибше розуміння, немає залежності від інструмента | повільніше на рутині (тести, DTO, конфігурації) |
| Копіювання готового рішення з мережі | швидко | пряме порушення доброчесності |
